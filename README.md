# SearXNG on Render

A private-ish [SearXNG](https://docs.searxng.org/) metasearch instance that deploys
to [Render](https://render.com) from GitHub using Docker. One free web service,
no database, no persistent disk, no extra infrastructure.

SearXNG queries other search engines and aggregates the results. It is **not** a
search index: queries still go to Google, Bing, Brave, DuckDuckGo, etc., from
Render's servers.

## Features

- Official SearXNG image, pinned to an immutable release tag (`2026.11.9-57ff753ad`)
- Runs as the unprivileged `searxng` user (UID 977)
- Listens on Render's injected `$PORT` on `0.0.0.0`, with graceful SIGTERM
- HTML UI and JSON API (`/search?format=json`)
- Google, Bing, Brave and DuckDuckGo enabled (plus all upstream defaults)
- No analytics, telemetry or tracking; autocomplete via Brave suggest
- Secrets generated by Render, never committed
- No Valkey/Redis, no paid services

## Deploy to Render

1. Push this repository to GitHub (commands below).
2. In the [Render Dashboard](https://dashboard.render.com): **New +** → **Blueprint**.
3. Connect the repository and click **Apply**. `render.yaml` creates one Docker web
   service on the **free** plan and generates `SEARXNG_SECRET`.
4. Wait for the first build (a few minutes). The service URL appears at the top of
   the service page: `https://<service-name>.onrender.com`.

Push commands:

```bash
git init -b main
git add .
git commit -m "Deploy SearXNG on Render"
gh repo create searxng-render --public --source=. --remote=origin --push
```

If you prefer the dashboard wizard instead of the Blueprint: **New +** → **Web
Service**, pick the repo, set **Language: Docker**, **Plan: Free**, and
**Health Check Path: `/healthz`**. Add an environment variable `SEARXNG_SECRET`
and use **Generate** for its value.

## Environment variables

| Variable | Required | Notes |
| --- | --- | --- |
| `SEARXNG_SECRET` | Yes | Flask secret + image-proxy HMAC key. Render generates it (`generateValue: true`) and keeps it stable. Changing it invalidates sessions and proxied image URLs. |
| `PORT` | Injected | Render sets it (default `10000`); the entrypoint passes it to Granian. Do not hardcode. |
| `SEARXNG_BASE_URL` | No | Absolute public URL, e.g. `https://searxng.onrender.com`. Only needed if you see wrong absolute links. |

`SEARXNG_SECRET` has no default: SearXNG refuses to start without it. That is why
the Blueprint generates one instead of relying on a value in the repo.

## Configure search engines

Edit [`searxng/settings.yml`](searxng/settings.yml), commit, and Render redeploys
automatically. Identifiers below are verified against SearXNG `2026.11.9`:

| Engine | Identifier | State in this repo |
| --- | --- | --- |
| Google (scraping) | `google` | Disabled: blocked from Render's IP; Google results come via `google cse` |
| Bing | `bing` | `disabled: false` (off by default upstream) |
| Brave Search | `brave` | Enabled by default upstream |
| DuckDuckGo | `duckduckgo` | Disabled: times out from Render's IP |
| Google CSE | `google cse` | Enabled by default upstream; provides Google results without an API key |

Notes:

- `google news`, `google scholar`, `google images`, `bing news`, etc. are **separate
  engines** with their own identifiers; enabling `google` does not enable them.
- `startpage` and `mojeek` are marked `inactive` upstream because they now require a
  proof-of-work CAPTCHA. Don't enable them.
- `braveapi` needs a paid API key; the HTML `brave` engine is what is enabled.
- Everything is merged over upstream defaults (`use_default_settings: true`), so you
  only list what you change.

## JSON API

```bash
curl -s "https://<service-name>.onrender.com/search?q=render.com&format=json" | jq '.results[0]'
```

JSON is enabled via `search.formats` in `settings.yml`. Same rate/abuse caveats as
the HTML UI apply.

## Free-tier limitations (by design)

- **Spins down after 15 minutes without traffic** and takes about a minute to wake.
  The first request after idle may show Render's loading page.
- **Ephemeral filesystem.** Nothing is persisted. The config is baked into the image
  and the secret comes from Render, so a restart is harmless; only the favicon cache
  is lost.
- **0.1 CPU / 512 MB.** Fine for personal use, not for many concurrent users.
- **750 free instance hours per workspace per month** (shared with other free services).
- **No limiter.** SearXNG's bot/rate limiter needs Valkey, which is a paid service on
  Render. Disabled deliberately; see `server.limiter` in `settings.yml`.
- This is not 24/7 uptime. Do not add pingers to fake activity; the free plan is
  explicitly not for production.

## Updating

Bump the image tag in `Dockerfile`:

```dockerfile
FROM ghcr.io/searxng/searxng:<new-version>-<commit>
```

Use tags from [Docker Hub](https://hub.docker.com/r/searxng/searxng/tags) or the
[GHCR mirror](https://github.com/searxng/searxng/pkgs/container/searxng). The repo
uses GHCR to avoid anonymous Docker Hub pull limits during builds. Commit and push;
Render redeploys on every push to the linked branch.

## Troubleshooting

- **Build fails pulling the image**: confirm the tag still exists on GHCR; tags are
  immutable, so a typo is the usual cause.
- **Deploy fails health check**: open the logs. The app must listen on `$PORT`. A
  missing `SEARXNG_SECRET` also aborts startup with an "Invalid settings.yml" error.
- **An engine returns errors / CAPTCHA**: Google and Bing commonly block datacenter
  IPs such as Render's. SearXNG suspends a failing engine for an hour (configured in
  `settings.yml`) and keeps serving results from the others. This is an upstream
  engine policy, not a deployment bug.
- **Slow first search**: cold start plus engine timeouts. The first query after idle
  can take several seconds.
- **Need rate limiting**: add a Render Key Value instance, set `valkey.url` in
  `settings.yml`, and set `server.limiter: true`. That is a paid add-on.

## Privacy

SearXNG does not log searches or create profiles, and this repo adds no analytics.
However, upstream engines still receive your query and see the request coming from
Render's IP address, not yours. Self-hosting SearXNG does not self-host Google's
index and does not make you anonymous to those engines.

## Local run

```bash
docker build -t searxng-render .
docker run --rm -p 8080:8080 \
  -e SEARXNG_SECRET="$(openssl rand -hex 32)" \
  searxng-render
# http://localhost:8080
```
